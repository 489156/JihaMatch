## 1. [최고 위험] 매물 DB 무단 수집 — 등급 D

### 1.1 확정된 판례

**① 네이버 v. 다윈프로퍼티 (특허법원, 2026. 1. 4., 2심)**

- 다윈프로퍼티가 2021. 2. 네이버 부동산 매물 DB를 크롤링해 다윈중개에 게시
- **2심 원고 일부 승소**: 복제·전송 금지, **8,000만 원 배상** (1심 7,000만 원 → 1,000만 원 증액)
- **다윈 서버 저장 데이터(가격·면적·동·층수 등 24개 항목) 삭제 명령**
- 재판부 인정 논지:
  - "네이버가 **약 10억 원**을 투입해 확인매물 시스템을 구축·유지했다"
  - "부동산 정보업체에서 매물 정보를 제공받았더라도 **네이버 시스템에 맞게 편집·배열**했으므로 **단순 이용자가 아니다**"
  - "**원본 자료를 직접 생성하지 않았더라도** 인력과 비용을 들여 정렬·가공하면 DB 제작자"

> 📌 **핵심 교훈:** "데이터 원천은 우리가 만들지 않았으니 우리 DB가 아니다"는 항변은
> **2026년 현재 법원에서 더 이상 받아들여지지 않는다.**

**② 직방 v. 방픽 (서울중앙지법 2023. 2. 3.)**
- 크롤링 데이터 폐기 + 2,000만 원 배상
- 직방 매물정보 약 45만 건 중 방픽 게재물 약 20만 건

**③ 잡코리아·사람인 계열 (2017~)** — 채용사이트 계의 동선 1.2 벽 3중 구조 (회피 불가)

| 벽 | 내용 | 효과 |
|---|---|---|
| 이용약관 | 네이버부동산·직방·다방·호갱노노 전부 "수집·복제·재가공·재배포 금지" 명시 | 형사 아님, **민사 손해배상 가능** |
| robots.txt | 매물 페이지 명시적 차단 | 기술적 강제력 없으나 **약관 위반의 증거**가 됨 |
| 봇 탐지 | 동적 렌더링 + 비정상 트래픽 패턴 탐지 → IP 차단 | 기술적 장벽 |

### 1.3 JihaMatch의 선택

**원문을 수집하지 않는다. 원문을 만들지 않는다. 원문을 재게시하지 않는다.**

| 금지 | 허용 |
|---|---|
| 매물 원문 저장 |(출처 URL + 식별자 + 딥링크)만 저장 |
| 매물 상세 페이지 재현 | **파생정보**: 점수, 실거래 대비 괴리, 총비용 산출 |
| 매물 목록 페이지 정렬 순위 | **자사 계산값**의 정렬. 원문 필드는 참조 링크 |
| 타사 매물 목록을 데이터셋으로 재사용 | **공식 공개 API**만 수집 |

## 2. [높음] 「공인중개사법」 제18조의2 제3항

> **"개업공인중개사가 아닌 자는 중개대상물에 대한 표시·광고를 하여서는 아니 된다."**

### 관련 조문
- ① 표시·광고 시 중개사무소 명칭·소재지·연락처·등록번호 + 개업공인중개사 성명 명시
- ② 인터넷 표시·광고 시 **소재지·면적·가격 등** 추가 명시
- ③ **개업공인중개사가 아닌 자는 표시·광고 금지**
- ④ 부당 표시·광고 금지 (존재하지 않는 매물, 거짓·과장, 거래질서 해치)

세부 기준: [중개대상물의 표시·광고 명시사항 세부기준](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=2100000250356) (국토부고시 제2024-748호, 2025. 1. 1. 시행)

### JihaMatch에 대한 적용성 검토

**우리가 중개를 하지 않는다.** 중개대상물의 표시·광고를 하지 않는다.
우리 화면에 있는 것은: (1) 사용자 본인이 입력한 조건, (2) 공개 API로 산출한 지표,
(3) **타사 원문 페이지로 연결되는 링크**.

### 그러나 — 회피해야 할 사례

| ❌ 하지 말 것 | 이유 |
|---|---|
| "이런 집 있습니다" 식의 매물 카드 렌더링 | 표시·광고 다툼 소지 |
| 중개사 연락처를 모아 우리 화면에 표기 | 사실상 중개 광고 |
| 매물 사진·설명을 그대로 옮겨 표시 | DB권 + 표시·광고 |
| "매출 가능" / "거래 가능합니다" 표현 | 표시·광고 해석 여지 |

> **국토부가 이미 「부동산 광고 시장 감시 센터」를 운영 중**이다
> (직거래 플랫폼 광고 500건 모니터링 → 부당 광고 104건 적발, 2024. 11. 기준 4주)
> 모니터링 대상은 중개 플랫폼이 아니다. **직거래 플랫폼이다.**
> → 직거래 모델로 갈 경우 감시 대상이 된다. 이는 이후 Phase 2 설계에 반영.

## 3. [중간 → 높음] 2026년 거래신고법 개정 — 직거래 플랫폼

**「부동산 거래신고 등에 관한 법률」 개정안, 2026. 5. 7. 국회 본회의 통과** (출처: 김앤장 데이터인사이트 2026년 5월 주요 내용)

### 신설 내용
| 항목 | 내용 | 시행 |
|---|---|---|
| 허위정보 유포 금지 | 거래 유인 목적 허위정보 유포 → **형사처벌 (1년 이하 징역 또는 2천만 원 이하 벌금)** | 공포 후 **6개월** |
| 직거래 매물 필수정보 명시 의무 | 소재지·면적·가격 등 | 공포 후 1년 |
| 부당 표시·광고 금지 | 허위매물 등 | 공포 후 1년 |
| **직거래 플랫폼 운영사업자 책임** | **게시자 신원 ↔ 매물 소유자 관계 확인**, 거래 시 유의사항 안내 | 공포 후 **1년** |
| 과태료 | 위 의무 위반 시 | 공포 후 1년 |

> **전략적 해석:** 이건 위협으로 보이지만 사실상 **규제 파괴의 창(window)** 이다.
> 직거래 플랫폼에 신원 대조 의무가 생기면, **인증을 통과한 매물 데이터는
> "합법적으로 신뢰할 수 있는 신호"로 부가가치가 생긴다.**
>
> **전제:** 수정·시행일이 공포 시점 기준으로 6개월/1년 후이므로
> 실제 시행일을 반드시 확인해야 한다. 이 문서 작성일(2026-10-07) 기준 아직 시행 전.

### JihaMatch에의 함의
- 직거래 모델을 선택한다면 **운영사업자 의무를 선제적으로 이행**하는 것이 차별점이 된다
- 증분: "인증을 통과한 매물만 우리 추천에 올린다" → **이 지표 자체가 상품**
- 2026-02-10 시행 [부동산 거래신고법 시행령 개정](https://www.law.go.kr/lsInfoP.do?lsiSeq=280211&viewCls=lsRvsDocInfoR) (대통령령 제35899호) 이후 추가 개정 여부 확인 필요

## 4. [높음] 개인정보 — 민감정보 처리

JihaMatch는 사용자의 **소득·순자산·부채·보유부동산**을 요구한다.
이것은 민감정보에 준하며 처리 난도가 일반 서비스와 차원이 다르다.

### 반드시 지킬 것

| 항목 | 조처 |
|---|---|
| **별도 동의** | 민감정보 수집은 동의를 다른 항목과 묶지 않는다 (별도 동의를 화면 단위로) |
| **수집 최소화** | 실거래·공고 API는 개인 식별자가 전혀 필요 없다. 프로필 입력만이 유일한 민감 데이터 수집 지점 |
| **암호화** | 재무 축은 필드 레벨 암호화. 평문 DB 금지 |
| **접근 최소화** | 내부자 조회 로그 전수 기록. 개발·운영 환경 분리 |
| **국외 이관 금지** | LLM API에 프로필을 보내지 않는다. **판정·요약은 로컬 규칙 엔진에서** |
| **보관 기간** | 목적 달성 즉시 파기. 사용자 요청 시 즉시 삭제 |
| **제거 권장** | "내 전체 데이터 삭제" 버튼. 백업까지 30일 내 완전 삭제 |
| **정보주체 열람** | 사용자가 자기 데이터에 무엇이 저장됐는지 조회 가능해야 함 |

> ⚠️ **LLM 사용 레드라인:** 사용자 재무 정보를 외부 LLM에 전송하지 않는다.
> 청약·비용 판정은 **결정론적 룰 엔진**으로 구현한다.
> LLM은 (일반화된) 설명문 생성에만 쓰고, 판정 값은 절대 생성하지 않는다.
> 이건 컴플라이언스가 아니라 재현성 문제이기도 하다 — 룰 엔진은 감사 가능하다.

## 5. [중간] '"나는 중개가 아니다"는 방어의 한계

중개를 하지 않는다는 것이 자동으로 안전을 보장하지 않는다.

### 금지 표현 (UI 카피 가이드)

| ❌ 쓰지 말 것 | ✅ 대신 |
|---|---|
| "추천 매물" | "조건에 맞는 매물 신호" / "이 조건으로 보기" |
| "이 집 사세요" | "이 단지는 예산 내에서 가능합니다" |
| "매출" | "현재 거래 신호 있음" |
| "최고의 선택" | "다음 조건에서 1위 — 이유 보기" |
| "무조건 가능" | "현재 확인된 조건으로는 가능합니다" |

### 권리분석·거래대행
- 등기부 해석, 권리관계 판단 → **전문가(변호사·공인중개사) 소개**. 자문하지 않는다.
- 소비자가 소액 소비자 분쟁에서 패소하면 **사건이 커질 수 있다** 위험이 있다.
- → "판정 결과는 참고용이며 권리·의무 관계를 발생시키지 않습니다"를 **모든 판정 화면에 상시 표시**

## 6. [중간] 개인정보 — 사용자 본인 동의 기반 수집 (Phase 2)

사용자가 자신의 계정으로 직접 로그인해 매물을 수집하는 브라우저 확장 모델.

### 예상 쟁점
| 쟁점 | 예상 논점 | 대응 |
|---|---|---|
| 이용약관 위반 | 로그인 자동화가 약관 위반인가 | 사용자 본인 데이터에 대해 문제 발생 가능성 — **법률 자문 필수** |
| DB권 | 수집 결과를 우리가 DB로 만들면 1번과 동일 | **사용자별 격리 저장. 대량 집합 DB 구축 금지** |
| 「공인중개사법」③ | "표시·광고"에 해당하는가 | 우리 화면에 재현하지 않고 **사용자 브라우저 안에서만** 표시 |
| 전달 | 제3자에게 제공 금지 | **절대 제공 금지** — 제공 순간 1번 판례로 직결 |

> **설계 원칙:** 사용자 본인 수집 데이터는 **해당 사용자 화면에서만** 소비한다.
> 전사 분석·다른 사용자 제공에 쓰지 않는다. 이 원칙을 어기면 모델 자체가 위험해진다.

## 8. 컴플라이언스 체크리스트 (구현 시)

- [ ] 모든 매물/공고 화면에 **원문 출처 + 딥링크** 표시
- [ ] 원문 HTML·이미지·설명문 저장/재현 **없음** (코드 레벨 강제 + 테스트)
- [ ] 민감정보 수집 화면에 **별도 동의 체크박스** (미체크 시 진행 불가)
- [ ] LLM API 호출 시 프로필 전송 **기술적으로 차단** (게이트웨이 레벨)
- [ ] 판정 결과 화면에 **면책 고지 상시 표시**
- [ ] 금감원/여권사 해당 기능 **구현하지 않음** (Phase 3 이전)
- [ ] 사용자 데이터 완전삭제 플로우 + 30일 백업 만료
- [ ] **Phase 0 종료 전 변호사 상담 1회** (3·6·3 항목)
- [ ] 개정 법령 감시 파이프라인 가동 (수정·시행일 반영)
- [ ] 매물 소스별 계약서 아카이브 (출처·라이선스·기간)
- [ ] **정책 이벤트 발송 전 공식 소스 2중 교차 확인** (가장 중요)
- [ ] 정책 이벤트에는 시행일·적용범위·원문 링크 3요소 필수
- [ ] 미검증 정책은 `PENDING_VERIFICATION`으로 보류하고 발송 금지
- [ ] 표시·광고 문구·자격 표기 자체 점검 로직 가동
- [ ] 판정 결과에 기계가 읽을 수 있는 산식·근거 조문·기준일 표기

## 9. 2026-11 조사 반영 — 정책 정보 진실성과 AI 노출 리스크

### 9.1 지라시 전파 리스크

국토교통부는 2026년 2월·6월·10월·11월 네 차례 "부동산 대책 지라시" 유포를 수사 의뢰했다.
11월 6일 유포된 문건(부천·수원 권선구·안양 만안구 규제지역 추가, 고가 아파트 대출 한도 축소)은
전부 사실이 아니었고 [리포트 58][리포트 59], 국토부는 "정책 사칭이나 사실 조작으로 시장에 혼란을
일으키는 행위에는 엄정 대응하겠다"며 확인 경로를 공식 누리집과 공식 SNS로 지목했다 [리포트 60].

**JihaMatch가 정책 이벤트를 알림으로 보내는 순간, 그 알림 자체가 허위정보 유통 채널이 될 수 있다.**

대응 규칙:

- 정책 이벤트 소스는 **공식 SNS + 공식 누리집 + 법령 API** 3중 교차 확인 후에만 확정한다.
- "보도자료 인용"이 아니라 **"시행일 확정 + 원문 링크"** 형태로만 전달한다.
- 부정 검증(지라시 식별)을 통과하지 못한 내용은 `PENDING_VERIFICATION`으로 보류하고 발송하지 않는다.
- 발행 주체·게시 시각·확인 시각을 함께 표시해 독자가 스스로 판단할 수 있게 한다.
- 공식 채널을 접촉한 지라시도 전제로 하되, **국토부 공식 계정·누리집·법령 API 3개가 모두
  일치할 때만** 확정 이벤트로 승격한다.

### 9.2 표시·광고 컴플라이언스

2025년 7월부터 2026년 6월까지 국토부는 인터넷 매물 광고를 점검해 위법 의심 1,412건을 적발했다.
상시모니터링 9,383건, 기획모니터링 1,029건이며 위반 유형은 부당한 표시·광고 5,201건(55.4%),
명의무 위반 3,753건(40%), 무자격자 광고 429건(4.6%)이었다 [리포트 61].
→ 유형별 자체 점검 로직을 구현 단계에 미리 넣는다. 표시·광고 문구, 자격 표기,
감면율·연도·대상 조건의 표기 정확성이 전부 점검 대상이다.

### 9.3 AI 검색 노출 리스크

AI 엔진이 사용자에게 부동산 앱을 추천하는 단계가 별도의 유통 채널이 되었고 [리포트 21],
그 추천 순위를 외부 서비스가 측정해 공개한다. 기회와 리스크가 동시에 생긴다.

- 기회: **근거 링크와 명시적 산식이 곧 AI 인용 가능성**이 된다.
- 리스크: 잘못된 수치나 오류 법리가 AI 인용으로 확산되면 출처로 인용돼 평판이 손상된다.
- 대응: 판정 결과 페이지에 산식·시행일·근거 조문을 **기계가 읽을 수 있는 형태**로 노출한다.
  구조화된 표, 단위 명시, 기준일 병기, 그리고 그 사실이 채널이 아니라 앱 내부 자산이 된다.
