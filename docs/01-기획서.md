## 0. 결론 요약

이 서비스의 본질은 "매물 추천"이 아니라 **"이사 가능성 판정 엔진"** 이다.

포털들은 사용자가 무엇을 팔 수 있는지, 얼마를 낼 수 있는지를 모른다.
그래서 걸러내기(필터)만 잘할 뿐 판단하지 못한다.
JihaMatch의 진입점은 **사용자 측 정량정보**다 — 청약자격, 순자산, 대출잔액,
가구구성, 통근 제약. 이것을 넣으면 필터가 아니라 **판정**이 되고,
판정 결과는 포털이 구조적으로 제공할 수 없는 것이다.

따라서:

1. **매물 원문을 다루지 않는다.** 파생정보(점수·판정·비용)만 만들고, 원문은 링크로 보낸다.
2. **공식 오픈API만 기반으로 한다.** 전부 무료·자동승인·제한없음. 1차는 웹 크롤링 0건.
3. **차별점은 정책 매칭이다.** 공고 + 청약자격 + 세제 + 금융을 하나로 잇는 룰 엔진.
4. **알림은 매물이 아니라 상태 변화다.** 좁고, 시간창이 있고, 행동으로 이어진다.

| 정책의 진실성 판정 | 국토부 지라시 유포 4회 수사 의뢰 (2026년) | 미선점 |

### 0.1.1 타깃 확장의 구조적 함의

타깃을 "주거용 및 투자용 부동산을 탐색하는 한국인 전체"로 넓히면 **판정 축이 갈린다.**

| | 주거 매매 | 투자용 주거용 건물 |
|---|---|---|
| 결정 축 | 자격 + 총비용 | 세제 + 수익성 + 계약가능성 |
| 핵심 입력 | 무주택 여부, 청약통장, 소득·순자산, 지역제한 | 취득세율, 양도소득세 중과, 종부세, 임대소득, 등록임대 감면 |
| 아파트 청약 룰 적용 | 적용 | **적용 안 됨** |

수익형 계산기 시장(수익방·sem2em·calcnow 등)은 이미 포화다. 따라서 투자 축의 빈틈은
**계산이 아니라 감시**에 있다. 등록임대 세액감면은 2028-12-31 일몰하고,
다주택 양도소득세 중과 유예는 2026-05-09 종료됐다. 이런 자동 감시 + 본인 조건 매핑이
남은 영역이고, 여기에 세제 영향액 산출을 얹는다.

### 0.1.2 신뢰 게이트 — 매물 수의 함정

서울 아파트 매매 매물은 2026-11-11 기준 8만 1,714건으로 연초 대비 40% 넘게 늘었다 [리포트 23].
그런데 서울 상위 10개 대단지(6만 6,480가구) 실제 전세 매물은 2,392건, **3.6%**뿐이다 [리포트 29].
플랫폼의 "매물 수"는 시장 재고가 아니라 **매물 게시의 누적량**이다.
"이 매물이 지금도 거래 가능한가"를 붙일 수 있는 서비스는 2026-11 기준 확인되지 않는다.

### 0.1.3 유통 채널 — GEO

오픈팩트 오픈랭킹이 2026-11-08 ChatGPT·Claude·Gemini·Perplexity·네이버 5개 엔진으로 측정한
아파트 시세 조회 앱 추천 순위는 호갱노노 100, 네이버부동산 91, 직방 85.8, 다방 82.7,
아실 23.5, KB부동산 22.9이며 상위 3개가 전체 언급의 57%를 차지했다 [리포트 21].
판정 엔진이 곧 유통 자산이 되는 구조다. 근거 링크와 명확한 산출식이 AI 인용률에 직결된다.

## 1. 문제 정의

### 1.1 사용자의 실제 불편 (가설 — 검증 필요)

한국에서 이사 결정을 내리는 데 걸리는 실제 경로:

```
지역 후보 좁히기  →  플랫폼 4~5개 병행  →  매물 3,000건 물어보기
   →  매번 같은 필터 재설정        →  시세/실거래를 다른 사이트에서 대조
   →  중개사 5명 방문 상담         →  계약금·세금·수리비 "이게 얼마지?"
   →  청약 자격? 지원받을 수 있는 것? 몰라서 포기
```

**찾는 데 문제가 아니라, 판단하는 데 문제가 있다.**
그리고 판단에 필요한 정보가 5개의 서로 다른 관영 체계에 흩어져 있다.

### 1.2 왜 아직 아무도 안 하는가

| 기존 서비스가 못 하는 이유 | 근거 |
|---|---|
| 개인정보 장벽 | 청약통장·소득·순자산·보유부동산은 민감정보. 매물 플랫폼은 이걸 요구할 수 없음 |
| 중립성 장벽 | 공인중개사는 매수자/매도자 어느 쪽도 아닌 제3자가 아님. 중개 의무가 있다고 설명·공시(disclosure) 부담 |
| DB권 장벽 | 매물 원문 확보 자체가 소송 대상이 됨 (네이버 v. 다윈 2심 2026. 1. 4.) |
| 수익 구조 | "판정 결과"는 정보가 아니라 가치. 광고로 환산하기 어렵다 |

이 4개 장벽은 **피해야 할 벽이 아니라 이 서비스의 진입벽**이다.
포털이 못 하는 것을 하는 게 곧 진입벽이 된다.

## 2. 타깃

### 2.1 1차 (Primary)

> **30~45세, 비수도권 또는 수도권 간 이동 검토, 지금 이사 결정을 3개월 안에 내려야 하는 1~2인 가구**

- 소득 5,000만~1.2억
- 청약자격 판단이 불확실한 계층 ("나 이 공고 떨어질 수 있나?")
- 전세/월세 매물 탐색은 능숙하지만 **총 비용 구조**를 모름
- 부산·대구·광주 → 서울 이주, 서울 → 생활권 이전, 타 지역 내부 이동

### 2.2 2차 (Secondary)

- 신혼부부 (출산 후 2년 내, 신축 아파트 또는 신혼매물)
- 1인 가구 (독거 1년 이상, 1인 가구 정책 수혜 가능)
- 복수주택(다주택)·사업자·투자성 매수 검토자
- **투자용 주거용 건물** (오피스텔·빌라 등 주거용 용도, 세제·수익성·계약가능성 관점)

### 2.3 Explicitly NOT (초기)

- 투자 타깃에서의 **가격 예측 기능 자체** (판정·총비용·세제 영향액 산출까지만)
- 상업·업무용 매물 (타깃은 '주거용 및 투자용 주거용 건물'로 한정)
- 에이전시·중개·프리미엄 타겟
- 주거용 외 상업·업무용 매물

## 3. 개인화 모델: 본인 조건 4축

프로필 입력은 **1회만**. 이후 자동 갱신 가능한 항목과 수동 항목을 분리한다.

### 축 1. 재무 (Financial)

| 항목 | 수집 방법 | 민감도 |
|---|---|---|
| 현금성 자산 (예적금·증권·코인) | 수동 | 중 |
| 보유 부동산 (현재 주소·시가·잔대) | 수동 | 중 |
| 대출 현황 (잔액·금리·만기·DSR) | 수동 | **상** |
| 월 소득 (근로/사업) | 수동 | **상** |
| 연 나이 | 수동 | 중 |
| 청약통장 가입기간·주택공급 개수 | 수동 | 중 |
| 무주택 여부 (실제 재산 기준) | 수동 | 중 |

> ⚠️ 이 축이 서비스의 해자(moat)다. 절대 타사에게 제공하지 않는다.
> 타사 제공 시 이 서비스는 "필터가 좋은 앱"으로 강등된다.

### 축 2. 자격 (Eligibility)

자격은 **사용자 입력에 의존하지 않고 공식 자료로 판정**해야 한다.

```
무주택 여부 ──┐
소득(연) ─────┤
순자산 ──────┼─→ 청약 자격 판정 (국민주택기금 / 주택공급 유형별)
부채 비율 ────┤
지역제한 ────┘
```

### 축 3. 제약 (Constraints)

- 통근: 직장/학교 주소 + 최대 통근시간 (지도 API로 isochrone 계산)
- 가구구성: 자녀 수·나이, 반려동물, 휠체어, 경로령
- 물리적 조건: 주차, 엘리베이터, 방 개수, 방향, 채광, 소음 민감도
- 예산: 총비 (매매가) vs 월 고정비 (대출 상환액)
- 일정: 희망 입주일, 잔금 지급일 (매매), 확정일자 지키기 (임대)

### 축 4. 환경 선호 (Preference)

- 선호/비선호 지역
- 재개발·재건축·도시계획 진행 중인 단지 (향후 가치)
- 학군, 생활 인프라 밀도
- 정주 위험: 개발계획의 **불확실성** 명시

## 4. 지역 스코어: 환경 데이터

SGIS(통계지리정보서비스) 생활권역 통계가 핵심 인프라다. 공짜, CC0, 집계구 단위.

| 지표 | 소스 | 갱신 |
|---|---|---|
| 인구·가구·고령화 | SGIS 인구통계/가구통계 API | census 주기 |
| 생활업종 (편의·의료·교육·문화) 밀도 | SGIS 생활업종 후보지 API | 사업체 survey |
| 통근시간 (지점 기반 생활권역) | SGIS + 지도 API isochrone | 실시간 계산 |
| 공시지가 | 한국부동산원 공시지가 API | 월 |
| 가격지수 | 한국부동산원 공동주택 실거래가격지수 | 월 |
| 거래 활동도 | 국토부 실거래가 집계 | 월 |

**스코어 조립 (예시, 가중치는 검증 대상)**

```
지역 적합도 = 0.30 × 통근 적합
           + 0.20 × 생활 인프라 밀도
           + 0.20 × 가격 적합 (내 예산 대비)
           + 0.10 × 학군/교육
           + 0.10 × 재개발·개발계획 트랙션
           + 0.10 × 정주 위험 (역행)
```

가중치는 **사용자가 조절 가능**하게 한다. "왜 여기가 1위야"를 설명 가능하게 만드는 것이
필터형 서비스와의 결정적 차이.

## 5. 매칭 엔진: 3종 판정

### 5.1 비용 총액 계산기 (Total Cost of Ownership)

사람들이 가장 자주 틀리는 부분. 매매가만 보면 3~8% 밀린다.

```
실 획득 비용 = 매매가
             + 취득세 (6억 이하 1%, 1주택 보유자 1억 이하 1% +지방세, 다주택 3%)
             + 중개보수 (매매 0.6~0.9%, 전월세 0.5~0.8%)
             + 잔수리·하자 (평형별 경험치 기반 추정)
             + 이사·원산 (거리에 비례)
             + 비품·가전 (신혼 1순위)
             + 대출 이자 (DSR 반영, 30년 고정 기준)
```

**각 항목에 근거·출처를 붙인다.** "이 금액은 ○○ 아파트 84㎡ 잔수리 통계치 기준"처럼.

### 5.2 청약/공급 자격 판정 엔진 (Rules Engine)

룰이 데이터베이스에 있어야 한다. 하드코딩 금지.

```yaml
rule: 수도권_/apt_일반공급
when: 공급유형 == "APT_일반"
then:
  - 무주택: {required: true, source: 국민주택기금}
  - 청약통장: {required: true, min_개월: null}
  - 지역제한: {check: 주소_기준_규제지역_판정}
  - 특별공급_우선순위: [생애최초, 신혼부부, 다자녀, ...]
effect: {eligible: bool, reasons: [...], headroom_score: int}
```

- 룰 버전 관리 + 시행일 관리 (2026-02-10 시행령 개정 같은 것 대응)
- 판정 결과는 **근거 링크와 함께** ("이 조건은 공인중개사법 시행령 제XX조 기준" )
- 판단 불가 시 "확인 필요"로 표시 (틀린 확신 주지 않기)

### 5.3 금융 적합 판정

- LTV / DTV (단순)
- **DSR (부채원입금률)**
- **스트레스 DSR** (금리 ↑ 시나리오)
- 기금부채, 전세반환상품, 선취급 비율
- 시나리오: **금리 +1%p / +2%p, 가격 -10%** 돌려보기

> 이 기능은 은행·여권사advice이 아니라 **자기 확인용 시뮬레이터**로 포지셔닝.
> 면상의 금융 권유·중개를 하지 않는다 (취급 시 금융위 규제 대상 활동).

## 6. 알림 설계: 이벤트가 메시지다

### 6.1 왜 매물 알림은 실패하는가

사용자 정리: 직방은 "알림 빈도가 높은 편", 조건을 넓히면 "하루에도 수십 건".
**알림은 많을수록 가치가 떨어진다.** 그리고 매물 알림은 행동으로 이어지지 않는다 —
"또 직방 알림이네" 하고 무시.

### 6.2 JihaMatch의 이벤트 유형

| 이벤트 | 조건 | 시간창 | 우선도 |
|---|---|---|---|
| `MATCH_FOUND` | 조건 100% 충족 + 실거래 대비 적정가 하위 X% | 소멸성 | 🔴 긴급 |
| `DISCOUNT_DEADLINE` | 입주권/예약특약/공고 마감 D-7, D-3, D-1 | 시간박스 | 🔴 긴급 |
| `POLICY_CHANGE_IMPACT` | 내 조건에 적용되는 법/세제/공고 변경 | 즉시 | 🟠 높음 |
| `RATE_CHANGE` | 금리 변동이 내 대출 조건에 영향 | 즉시 | 🟡 보통 |
| `PRICE_SIGNAL` | 관심 단지 실거래가 N% 하락 | 지속 | 🟡 보통 |
| `INFRA_CHANGE` | 학구/개발계획/교통 개통 | 드물음 | 🟢 낮음 |

### 6.3 알림 원칙

1. **하루 1회 다이제스트** 기본. 긴급만 즉시.
2. 알림 본문 3줄 이내. 첫 줄이 판단 근거.
3. 모든 알림에 **행동 CTA 1개** (투어 예약 / 공고 바로가기 / 이 조건 저장).
4. **해지가 한 번의 탭.** 알림 3회 무응답 시 자동 쿨다운.
5. 알림에도 **"왜"** 를 붙인다. "왜 이 공고가 나한테?" 에 답해야 구독이 유지된다.

## 7. 로드맵

### Phase 0 — 검증 (2주)

목표: **사람이 이걸 실제로 원하는가.**

- [ ] 청약자격 판정 + 총비용 계산기를 **CLI/노션 페이로드로** 먼저 만든다 (앱 X)
- [ ] 20명 인터뷰 (이사 1년 이내 계획자)
- [ ] **법률 자문 1회** (03-법적리스크.md 관련)
- [ ] 의사결정 게이트: "사람이 이 도서를 스스로 쓰며 돈 내겠다고 하나?"

> ⚠️ 이 2주를 건너뛰고 코드를 먼저 쓰면 99% 확률로 막다른 논문자가 된다.

### Phase 1 — MVP (6~8주)

공식 API만으로 완결 가능한 범위. **매물 계층 없음.**

- 프로필 4축 입력 (수동)
- 비용 총액 계산기 + 시나리오
- 청약자격 룰 엔진 v1 (수도권/비수도권 APT 일반 + 특별공급)
- 지역 스코어 (SGIS + 공시지가 + 가격지수)
- 알림: LH·HUG·REB 공고 + 기준금리 + 관심단지 실거래 시그널
- 웹 앱 (Next.js) + 딥링크 위임

**성공 기준:** 가입자 중 30% 이상이 2주 내 "이 공고 나 자격 있다/없다" 판정을 자발적으로 사용.

### Phase 2 — 매물 신호 계층 (6주)

합법 경로만. 우선순위:

1. **직거래 오픈 플랫폼 연동** (당근·번개장터·중고나라 등) — 공개 API가 있다면
2. **사용자 본인 동의 기반 수집** (브라우저 확장)
3. **직거래 플랫폼 운영사업자 등록** (2027년 의무사항 시행 후)
4. 제휴/라이선스 계약

> 원문 저장·재게시는 이 Phase 전체에서 **금지**. 파생정보만 저장.

### Phase 3 — 관계 확장 (추후)

- 이사/수리/가전/insurance 제휴 리퍼럴
- 부동산 포트폴리오 자산 시뮬레이터
- 가족 공동 플랜 (배우자·자녀 선호 반영)

이 기획이 죽는 시나리오를 **미리** 적어둔다.

| # | 가정 | 죽는 시나리오 | 검증 방법 | 죽으면 |
|---|---|---|---|---|
| A1 | 사용자가 재무 정보를 입력한다 | 민감정보 요구 → 이탈 90% | Phase 0 인터뷰 20명 | "신용/조건 판단"을 간접입력으로 |

| A3 | 매물 신호를 합법적으로 얻을 수 있다 | Phase 2 전부 불가 | Phase 1 종료 시점에 계약 현실성 확인 | 매물 계층 영구 포기, 공고·정책만 |
