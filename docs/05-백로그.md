## Phase 0 — 검증 (2주) · 게이트 필수

> **이 단계를 건너뛰면 99% 확률로 막다른.**

### P0-1. 변호사 상담 (1회)
- [ ] 「공인중개사법」 18조의2③ 적용 관계 — **중개 아님을 어떻게 구조적으로 증명하는가**
- [ ] 사용자 본인 동의 기반 매물 수집의 법적 가능성 (03-법적리스크 6절)
- [ ] 2026-05-07 거래신고법 개정 직거래 플랫폼 의무 → JihaMatch에의 영향
- [ ] 사용자 재무 정보(소득·순자산·부채) 수집 시 동의·보관 설계 적합성
- **산출:** 서면 의견서. **이 문서와 충돌하면 설계를 바꾼다.**

### P0-2. 비용 계산기 + 청약 판정 (노트북에서)
- [ ] 총비용 계산 (취득세·중개보수·잔수리·이사·비품·대출이자)
- [ ] 청약자격 룰 v1 (수도권/비수도권 APT 일반공급 + 특별공급)
- [ ] 근거 링크 필수
- [ ] **"판단 불가" 상태를 먼저 구현** (불가능 판정이 아니라)
- **산출:** 동작하는 노트북/CLI 데모

### P0-3. 사용자 인터뷰 20명
- [ ] 연락처 확보 (지인·커뮤니티·지금 이사 고민 중인 사람)
- [ ] 검증할 가정: A1(재무정보 입력 의사), A2(판정 신뢰), A4(필터 대비 우월)
- [ ] **반대 의견을 적극적으로 경청** — "이거 필요 없어요"가 가장 값지다
- **산출:** 가정별 통과/실패 판정

### P0-4. 🛑 게이트
- [ ] "돈 내겠다고 하는 사람이 5명 이상인가?"
- [ ] "판정 결과를 보고 '이거 알아야 했다'가 나오는가?"
- [ ] ⛔ 아니면 → **설계 변경 또는 중단.** 코드 작성 금지.

### P0-5. 경쟁사·정책 모니터링 상시화 (조사 → 감시)
- [ ] 직방·호갱노노·네이버·다방·KB 신규 기능 릴리스 노트를 주 1회 점검
- [ ] 국토부 공식 X·Threads 피드 파싱 파이프라인 (지라시 대피 최우선 소스)
- [ ] **GEO 지수 오픈팩트 오픈랭킹 주간 스냅샷** (호갱노노 100 / 네이버 91 / 직방 85.8 기준선)
- [ ] "매물 수 vs 실제 재고" 신뢰 게이트 로직 설계 (서울 상위 10대단지 전세 매물 3.6% 케이스)
- **산출:** 주간 모니터링 노트 + 경보 규칙 1차안

## Phase 2 — 매물 신호 (6주) · 조건부

**전제: Phase 1이 매물 없이 성립했음을 먼저 확인.**

### P2-1 직거래 오픈 플랫폼 API 조사
- [ ] 당근·번개장터·중고나라·복덕빵 공개 API 존재 여부
- [ ] 이용약관, robots.txt, 상표·DB권 조건 확인
- [ ] **없으면 여기서 멈추고 다른 경로 탐색**

### P2-2 사용자 본인 동의 기반 수집
- [ ] 브라우저 확장
- [ ] **사용자별 격리 저장. 대량 집합 DB 구축 금지**
- [ ] 수집 데이터는 해당 사용자 화면에서만 소비
- [ ] 법리 자문 결과 반영 (P0-1 항목)

### P2-3 파생정보 생성
- [ ] 실거래 대비 괴리 계산
- [ ] 소진성 판정 (등록 후 X일 경과, 가격 변동)
- [ ] **원문 필드 재현 금지** — 점수·요약만

### P2-4 (선택) 직거래 플랫폼 운영사업자 등록
- [ ] 2026-05-07 개정 시행일 확인

- [ ] → **"인증 통과 매물만"이 상품화 지점이 될 수 있음**

### P2-5. AI 검색 노출(GEO) 대응
- [ ] 판정 결과를 기계가 읽는 구조로 노출 (단위·기준일·산식·근거 조문·원문 URL)
- [ ] 앱 이름·서비스 설명·기능 표기를 AI가 인용하기 쉬운 형태로 정리
- [ ] 월 1회 GEO 지수 스냅샷 비교 + 하락 시 원인 추정
- [ ] 조회수에 의존하지 않는 공개 신호 축 확보 (자체 제공 통계·산식 공개)
