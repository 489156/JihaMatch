## 1. 요약

JihaMatch는 **부동산 시장과 정책을 잘 알지 못하는 일반인**을 대상으로, "매물을 찾는 곳"이 아니라 **"집을 사도 안전한가, 그러면 언제부터 뭘 해야 하는가"를 알려주는 결정 대행 에이전트**다.

사용자는 조건을 직접 세팅하지 않는다. "안산에서 서울로 가고 싶다, 통근 40분, 예산 5억"이라는 한 줄짜리 목표를 말하면, 시스템이 나머지 조건을 추정해 자리 잡고, 지금 가능한 선택지와 불가능한 것을 이유·근거와 함께 판정하며, 각 선택지에 첫 걸음·기한·필요 서류를 붙여준다.

가치를 정보량이 아니라 **실패 비용의 감소**로 정의한다. 잘 모르는 사람이 잃는 가장 큰 돈은 놓친 기회(기회비용)와 잘못된 계약(계약 손실), 과다 세금이고, 이 셋을 줄이는 것이 JihaMatch의 유일한 목표다.

## 3. 배경

### 3.1 이 서비스의 전제: 사용자는 부동산을 모른다

기존 JihaMatch 기획은 "청약자격 판정 엔진"을 해자로 세웠다. 2026년 11월 시장 조사 결과, 그 해자는 이미 선점됐다.

| 확인된 사실 | 출처 |
|---|---|
| 직방 '청약진단 리포트'(2026-01-16)가 특별공급 10종 + 일반공급 12개 유형의 자격 충족 여부·경쟁강도·당첨자점수를 제시 | [리포트 5] |
| 호갱노노도 '공공·민간분양 청약 자격을 한번에 점검해보는 청약 진단'을 운영 | [리포트 2] |
| 직방 '지킴진단'(2026-04-18)이 주소 입력만으로 전세사기·권리분쟁을 점검 | [리포트 8] |
| 다방은 '안심진단'·'AI 동네이야기 분석'을 제공 | [리포트 17][리포트 18] |
| KB '찾아줘 내집'은 256만 매물에서 여러 '매물집사'가 추천 | [리포트 20] |
| 네이버 AI탭 이용자 1,000만 명(2026-07-15), 8월 부동산 매물 에이전트 공개 예정, 11-12 네이버페이는 "매물 검색 → 중개사 상담 연결" 구상 공개 | [리포트 13][리포트 10][리포트 14] |

**이 표의 함의는 하나다.** "아파트형 조건 판정"과 "매물 추천"은 이미 시장이 채운 영역이다. 경쟁사가 판정에 사용하는 입력값(무주택 여부, 통장 납입 개월, 전용면적, 전세가율, 용적률)은 **모르는 사람에게는 입력할 수 없는 값**이다.

### 3.2 그래서 관점을 바꾼다: 정보가 넘치는 게 아니라 판단의 출발점이 없다

2026년 3월 실제 리뷰 테스트에서 나온 결과다.

- 직방만 단일 질문으로 "반려동물 가능 여부"와 "강남·여의도 대중교통 1시간 10분 이내" 같은 복합 통근 조건을 동시에 해석했다.
- 다방·네이버페이·KB부동산은 질문을 반복해야 했다. 네이버페이의 AI 질문권은 주 5회(매주 월요일 갱신)로 제한됐다.
- 직방도 조건보다 낮은 면적(7.3평) 매물을 제시하고 반려동물 가능 정보를 각색했다. [리포트 15]

**성능 격차가 있어도 양쪽 모두 오류가 있다.** 이건 모델 성능 문제가 아니라, 모든 서비스가 **사용자가 이미 조건을 언어화할 수 있다고 가정하기 때문**이다.

모르는 사람의 실제 상태는 이렇다.

1. 내 조건을 글로 정리할 수 없다 (무주택인지, 소득이 얼마인지, 가족이 몇 명인지부터 막힌다)
2. 검색엔진에 무엇을 쳐야 하는지 모른다
3. 전용면적·용적률·전세가율을 모른다
4. 앱은 여럿 켜봤는데 각자 다른 말로 말해서 한 장으로 정리되지 않는다
5. 무엇을 모르는지부터 모르므로 "무엇을 찾아야 하는지"도 모른다

이 상태에서 "매물을 추천"하는 서비스는 아무리 정확해도 **입력 앞에서 막힌다.**

### 3.3 시장 조사가 남긴 빈틈 (심층 조사 결과 요약)

전체 조사 보고서: [`research/한국_부동산_정보·판정_시장조사_2026-11.md`](../research/한국_부동산_정보·판정_시장조사_2026-11.md) (출처 81건)

**빈틈 3개.**

| 축 | 왜 아직 비어 있는가 |
|---|---|
| 시장 전체를 관통하는 실현 가능성 판정 | 모든 AI 추천이 자기 매물 창고 안에서만 조건을 적용한다. 타사 매물·공급·공시를 관통하는 서비스는 2026-11 기준 확인되지 않는다 |
| 공급 파이프라인 × 개인 조건 | 호갱노노 '분양 예정'[3]과 네이버 '분양계획'[16]은 입고 목록을 주지만 개인 조건과의 대조는 주지 않는다 |
| 정책의 진실성 판정 | 국토교통부는 2026년 2·6·10·11월 네 차례 "부동산 대책 지라시" 유포를 수사 의뢰했다 [58][59]. 검증하는 서비스는 없다 |

**신뢰 게이트.** 서울 아파트 매매 매물은 2026-11-11 기준 8만 1,714건으로 연초 대비 40% 넘게 늘었다 [23]. 그런데 서울 상위 10개 대단지(총 6만 6,480가구)의 실제 전세 매물은 2,392건, **3.6%**뿐이다 [29]. 플랫폼의 "매물 수"는 시장 재고가 아니라 **매물 게시의 누적량**이다. 거래가 끝났는데도 삭제되지 않은 매물이 계속 쌓인다.

**공급 데이터는 추정 없이 조회할 수 있다.** SH는 착공일·준공일을 표로 공개한다. 2026년 기준 시공 중 9개 단지 5,455세대, 2026년 신규 착공 2개 단지 1,558세대, 임대 9,777호(건설형 126·매입형 4,651·임차형 5,000), 택지 11개 지구 93필지 257,475.6㎡ [30][31]. GH 공고 2,147건 [32]. 정비구역은 전국 4,727개가 사업단계별로 구조화돼 있다 [35]. 리츠부동산매물정보에는 공공기관의 미분양 주택·유휴부지 매각이 용도·인허가 단계와 함께 기재돼 있다 [36][37]. **"3년 이내 입주"는 계산이 아니라 조회로 나온다.**

**분포를 조심해야 한다.** 같은 이름 "전세수급지수"가 최소 3종 산식으로 쓰인다 (한국부동산원 서울 122.5 / 한국부동산원 연중 108.4 / KB 자사산식 전국 174.5) [25][26][27]. 화면에 "서울 아파트 전세수급지수(한국부동산원, 2026-11-01 기준 103.5)"처럼 출처·산식·기준일 3요소를 붙이지 않으면 어떤 지수인지 알 수 없다.

## 4. 목표

### 4.1 목표 문장

> **부동산을 모르는 사람이 스스로 조건을 세팅하지 않아도, "지금 나에게 가능한 선택지"와 "그 첫 걸음"을 알 수 있게 한다.**

### 4.2 무엇이 달라지는가

| 지금 (사용자가 직접 함) | JihaMatch 이후 (시스템이 함) |
|---|---|
| 전용면적·용적률·전세가율을 검색창에 입력 | "집 사야 해요" 한 줄에서 조건을 추정하고, 추정치를 먼저 보여줌 |
| 여러 앱을 오가며 시세·매물·공고 비교 | 한 화면에 "가능 / 놓치면 아쉬움 / 지금 하면 안 됨" 3칸 |
| 공급 공고가 올라오면 직접 찾아 확인 | "당신이 신청할 수 있는 공고"만 찾아서 판정 |
| 청약 탈락 이유를 모른 채 탈락 | 탈락 조건과 그 조건을 맞출 방법을 미리 제시 |
| 계약 후에야 세금·권리를 확인 | 계약 전에 세제 영향액과 권리 신호 금액을 확인 |
| 정책 뉴스를 봤는데 진짜인지 모름 | 공식 소스 2중 확인 후에만 "시행일 확정"으로 전달 |

### 4.3 OKR (첫 6개월, 상대 기간 기준)

**Objective: 모르는 사람에게 판정과 첫 걸음을 전달한다.**

| KR | 측정 지표 | 목표치 | 측정 방법 |
|---|---|---|---|
| KR1 | 주간 실행 사용자 수 (판정 결과 중 실제 행동을 1건 이상 실행) | 1,000명 | EventBus 실행 이벤트 중복 제거 기준 |
| KR2 | 판정 정확도 (사용자 확인 표본 100건 기준 정합률) | 95% 이상 | 분기 1회 표본 검증 + 사용자 "이거 틀렸어요" 신고율 2% 이하 |
| KR3 | 알림 → 첫 걸음 실행 전환율 | 25% 이상 | 알림 클릭 후 7일 내 실행 이벤트 발생 |
| KR4 | 무료 → Pro 전환율 | 3% 이상 | 구독 결제 시작 기준 |
| KR5 | 판정 커버리지 ("확인 필요"로 빠지는 비율의 역수) | 85% 이상 | 판정 결과 중 수동 확인 필요 비율 15% 이하 |

**KR2는 신뢰의 최하선이다.** 한 번이라도 "이 말 틀렸다"가 반복되면 모르는 사람은 즉시 이탈한다. 그래서 KR2는 기능 완성도보다 우선순위가 높다.

### 4.4 무엇이 아닌가 (이번 판의 성공 정의에 포함하지 않는 것)

- 매출. 첫 6개월의 목표는 매출이 아니라 **판정 정확도와 실행 전환**이다.
- 사용자 수. 1,000명 실행 사용자가 붙기 전까지는 마케팅 코호트를 붙이지 않는다.
- 경쟁 서비스 기능 복제. 매물 추천·시세·청약진단·수익률 계산기를 만들지 않는다.

## 5. 시장 세그먼트

### 5.1 타깃 정의: 부동산 문해력 0~1단계

이 서비스의 타깃은 **부동산 시장과 정책에 대해 잘 알지 못하는 모든 일반인**이다. 이미 지식이 충분하거나 직접 정보를 수집하고 있는 사람에게는 불필요한 서비스다.

**문해력 스펙트럼**

| 단계 | 상태 | 이 서비스의 관계 |
|---|---|---|
| **L0 전무** | 부동산 용어를 모른다. 전용면적·용적률·전세가율·청약통장·LTV의 뜻을 모른다. 내 조건을 설명할 수 없다 | **핵심 타깃** |
| **L1 기본만** | "특약", "신혼부부", "전세보증금"은 안다. 하지만 절차·순서·기한·서류를 모르고, 어디서 시작할지 모른다 | **핵심 타깃** |
| **L2 어느 정도** | 공고·시세·실거래를 직접 찾아본 경험이 있고, 무엇을 봐야 하는지 알고 있다 | **배제.** 직방 청약진단·네이버 AI탭·KB 내집내집으로 충분하다. 오히려 이 제품의 경쟁자 |
| **L3 전문** | 공인중개사·여권사·부동산 컨설팅·기관 | **배제.** B2B 별도 제품 필요 |

**L2를 배제하는 이유.** L2 사용자에게 "지금 가능한 것과 첫 걸음"을 알려주는 것은 정보량도 편의도 늘리지 못한다. 오히려 L2의 유일한 가치는 "내 조건을 넣으면 무엇이 필터링되는지"인데, 이건 이미 직방·호갱노노·네이버가 한다. **L2를 좁힐수록 L0/L1가 쓰는 제품이 된다.**

### 5.2 상황 기준 세그먼트 (인구통계가 아니라 문제 기준)

세그먼트는 나이·직업이 아니라 **"지금 무슨 상황에서 막혀 있는가"**로 나눈다.

#### S1 — 첫 집을 사야 하는 사람 (신규 진입자)

| 항목 | 내용 |
|---|---|
| 상황 | 집을 사야 하는 시점이 왔지만 어디서 시작할지 모름. 무주택이거나 청약 자격 여부도 모름 |
| 핵심 질문 | "나 지금 집 살 수 있어? 뭘 먼저 해야 해?" |
| 성숙도 | L0~L1 |
| 실패 비용 | 청약 탈락 후 통장 24개월 소진. 엉뚱한 계약 후 해지·보증금 소실 |
| 우선 기능 | ① 조건 자동 구성 → ② 가능/불가 판정 → ③ 첫 걸음(통장, 전용면적 방향, 후보 지역 좁히기) |
| Phase | **Phase 1** |

#### S2 — 갈아타기·개선 (보유자)

| 항목 | 내용 |
|---|---|
| 상황 | 현재 집이 맞지 않거나 비용 부담. 팔고 사야 하는데 순손실을 계산하는 방법을 모름 |
| 핵심 질문 | "지금 팔아야 하나? 팔면 세금·대출이 어떻게 달라져?" |
| 성숙도 | L1 (자기가 산 경위는 안다) |
| 실패 비용 | 양도소득세 중과(2026-05-09 유예 종료)·종부세·취득세 과다 [63][64]. 보유 상태를 모른 채 매수 |
| 우선 기능 | ② 세제 영향액 판정 + ③ 매도·매수 순서 |
| Phase | **Phase 1** |

#### S3 — 첫 투자 (초보 투자자)

| 항목 | 내용 |
|---|---|
| 상황 | 투자는 하고 싶은데 무엇을 봐야 하는지 모름. 수익률 계산기만 켜고 있음 |
| 핵심 질문 | "이 건물은 나한테 맞는가? 세금은? 계약은?" |
| 성숙도 | L1 |
| 실패 비용 | 지식 없는 사람의 투자는 실패 비용이 가장 크다. 무상임대·전세반환·의무귀속 기간 미인지 |
| 우선 기능 | ② 세제·수익성 + ③ 계약 리스크 |
| Phase | **Phase 2** (Phase 1에서는 S1·S2에 집중) |

**S3를 Phase 2로 미루는 이유.** "부동산을 모르는 사람"에게 투자는 가장 위험한 영역이다. 같은 무모함이 전세에서는 수리비 20만 원을 아끼게 하고, 투자에는 1억 원을 잃게 한다. Phase 1에서 사고를 만들면 "부동산을 모르는 사람에게 투자를 시키는 서비스"가 되어 브랜드가 파괴된다. **Phase 2 진입 조건은 교육 모듈(용어 사전 + 위험 체크리스트) 완비와 Phase 1 D30 리텐션 30% 이상**으로 못다.

#### 명시적 배제

- **공인중개사·여권사·부동산 컨설팅 종사자** — B2B 별도
- **부동산 지식 L2 이상** — 5.1 참조
- **특정 사해 지원**(전세사기 피해 등) — 전문 지원 조직의 영역
- **자기 집 단기간의 차익 실현 목적** — 이 서비스의 판정 깊이로 대응하지 않음

## 6. 가치 제안

### 6.1 경쟁 우위 3단 체인

경쟁 서비스는 이 체인의 앞부분만 한다.

```
[1] 이해시키기      [2] 판정하기              [3] 시작하게 하기
목표 → 조건 역추론  조건 → 가능/불가 판정      가능 → 첫 걸음·기한·서류
   ↑ 선점됨(부분)      ↑ 직방·호갱노노 선점      ↑ ★ 전무 ★
```

**이 제품과 가장 가까운 경쟁자는 리서치에서 확인된 "집값박사(zipgab-doctor)"다.** Threads에서 "3년 만에 순자산 18억 만든 실전 부동산 투자자"를 자칭하며 내집마련 후보 비교·시세추적·임장관리·자산관리·내집마련 지역 추천을 넣었다 [53]. 다만 이 서비스도 **맞춤형 필터 + 정보 제공** 구조이고, "지금 무엇을 해야 하는가"를 다루지 않는다. 1인 개발자 서비스라는 점도 규모 격차가 있다. JihaMatch는 그 사이가 아니라 **다른 축(실행 단계)**에서 경쟁한다.

### 6.2 세 가지 가치

#### 가치 1 — 모름의 감소: "무엇을 모르는지"를 알려주는 서비스

모르는 사람의 최대 비용은 모르는 것 자체가 아니라 **모르는 줄 모르고 행동하는 것**이다.

- 청약 탈락 조건을 모른 채 신청한다
- 세금을 모른 채 계약한다
- 거래되지 않은 오래된 매물을 진짜 집으로 믿는다
- 지라시를 정책으로 믿는다

JihaMatch는 **"확인 필요"를 정직하게 말한다.** 판정할 수 없는 것은 판정하지 않는다. 이것이 정확해 보이는 것보다 느려도 정직한 이유다.

#### 가치 2 — 시간의 절약: 검색을 대신하는 판단

사용자는 2~4시간을 써서 **결정하지 못한 상태**를 만든다. JihaMatch는 그 시간을 60초의 입력과 주 1회 3칸 요약으로 줄인다. 더 중요한 것은 **탐색을 멈추게 한다**는 것이다. 검색은 끝이 없다. 판정은 끝난다.

#### 가치 3 — 실패 비용의 감소: 원화를 붙여 말한다

모든 판정에 금액을 붙인다.

| 상황 | JihaMatch가 말하는 것 |
|---|---|
| 지금 확정 안 하고 지나가면 | "이 단지 84㎡는 3개월 사이 평균 4,100만 원 올랐어요. 같은 평형·같은 층 기준입니다" |
| 세금을 지금 알면 | "지금 사서 6년 보유하면 실효세율 14.9%, 4년이면 19.6%예요" |
| 이 집을 사면 | "이 단지는 14개월간 거래가 없어요. 실거래가 확인되지 않는 집이에요" |
| 지금 하면 안 되는 것 | "내 소득으로는 이 단지는 대출이 안 돼요. 잔여 세대 2채인데 경쟁자 43명이에요" |

정보는 무르고 **금액과 기한**만 남기는 게 요약 규칙이다. 모르는 사람은 숫자로 결정한다.

### 6.3 왜 경쟁하지 않는가 (Non-goals)

| 영역 | 경쟁 서비스 | JihaMatch의 선택 |
|---|---|---|
| 매물 탐색·추천 | 직방 AI중개사, 다방 AI방찾기, 네이버 AI탭 | **하지 않는다.** 딥링크로 보낸다 |
| 시세 조회 | 전 서비스 | **하지 않는다.** 필요한 시세만 판정 근거로 인용 |
| 청약자격 단일 판정 | 직방 청약진단, 호갱노노 청약 진단 | **하지 않는다.** "어떤 공고"를 찾는 것부터 담당 |
| 수익률·총비용 계산 | 수익방, sem2em, calcnow 등 다수 | **계산만 하지 않는다.** 계산 + **일정 자동 감시** |
| 정비사업 사업성 분석 | 정비닥터, 재개발닷컴 | **하지 않는다.** |
| 가격 예측 AI | 리치고 등 | **하지 않는다.** |
| 중개·대행·권유 | — | **하지 않는다.**Phase 3 리퍼럴도 권유 금지 |

**이 목록이 이 제품의 지도다.** Listed 항목이 "하지 않는다"는 것은 곧 사용자를 그쪽으로 보내겠다는 뜻이고, 그게 **정보가 넘치는 문제의 해법**이다.

### 6.4 해자(Barriers to Entry)

| 해자 | 설명 | 유지 방식 |
|---|---|---|
| 사용자 조건 프로필 | 직방·호갱노노가 복제할 수 없는 유일한 데이터 축. 본인의 재무·자격·제약·선호 | 절대 외부 제공 안 함, 사용자 본인이 원할 때만 |
| 실행 단계 데이터 | "이 공고에서 첫 걸음으로 무엇을 하고, 그 다음이 무엇이고, 서류가 무엇인지"의 연결 구조 | 매주 갱신되는 운영 비용. 수집만으로 안 된다 |
| 신뢰 게이트 데이터 | 거래 실증 여부·오래된 매물·삭제된 게시 판정 | 공식 API + 실거래 데이터를 계속 대조해야 유지 |
| 정책 검증 이력 | 지라시 재발 시 즉시 차단하는 거부 목록 | 시간 자산. 시작할수록 강해진다 |

**Weakness acknowledgment.** 경쟁자가 복제하려면 결정론적 룰 엔진 + LLM 설명 + 실행 단계 DB가 필요하므로 즉시 따라올 수 없다. 하지만 **사용자 프로필 축을 확보하지 못하면 그 차이는 사라진다.** 그래서 프로필 입력은 MVP 최우선이다.

**설계 규칙.** 카드에서 바꾸는 건 **5개 항목 중 하나만** 고치면 되게 한다. "Jagobar"를 다시 쓰게 하지 않는다. 추정한 항목은 **추정이라고 명시**하고, 그 추정이 판정을 바꾸는 경우에만 입력을 요청한다. 입력 요청은 스크린당 1개.

#### 7.1.3 메인: 3칸 대시보드

매일 세 개의 카운터가 아니라, **판정과 실행을 분리한다.**

```
┌─────────────────────────────────────────────────────────────┐
│  JihaMatch          2026년 11월 14일 금요일                  │
│  [ 🔔 알림 2 ]     [ 내 조건 확인 ]                          │
├───────────────────────────┬─────────────────────────────────┤
│ ✅ 지금 가능한 것         │ ⏳ 놓치면 아쉬운 것 (1개월)      │
│                           │                                 │
│ 1. 분당 신축 84㎡          │ • 용산 재개발 매물              │
│    공급가 6.1억            │   12/3 일반공급 9,840세대        │
│    → 일반공급 자격 충족   │   놓치면 2027년 6월으로 밀림       │
│    → 첫 걸음: 통장 24개월 │                                 │
│      (현재 11개월, 부족)  │ ⚠️ 지금 하면 안 되는 것         │
│                           │                                 │
│ 2. 용인 주공 84㎡          │ • 노량진 재개발 매물              │

│    → 내 조건 전부 충족    │   → 추천: 12월까지 기다리기       │
│    → 첫 걸음: 총비용      │                                 │
│      3.72억 (취득세 포함) │                                 │
└───────────────────────────┴─────────────────────────────────┘
```

**설계 규칙**

| 규칙 | 내용 |
|---|---|
| 칸은 항상 3개 | 가능 / 놓치면 아쉬움 / 지금 하면 안 됨. 늘 3칸. 예외 없음 |
| "지금 하면 안 되는 것"을 반드시 둔다 | 가장 신뢰를 높이는 요소. "이건 사지 마세요"를 말해줘야 "사도 됩니다"를 믿는다 |
| 첫 걸음은 항상 1문장 | "통장 24개월" "총비용 3.72억" "12/3까지 신청" |
| jargon 금지 | "잔여 세대" → "아직 안 팔린 집", "DSR" → "월 상환액이 월 수입의 몇 %" |
| 금액·기한 우선 | 근거 조문은 접이식으로 접어 둠. 기본은 숫자 |

### 7.2 핵심 기능 상세

#### F1. 조건 자동 구성 (역추론 엔진)

**무엇인가.** 사용자의 목표 문장에서 재무·자격·제약·선호 4축 조건을 추정한다.

**동작**

1. 입력을 4축으로 파싱한다. 어휘 매칭이 아니라 규칙 + 가중치 + 최근접 사례 조회 방식
2. 부족한 축은 **표준 가정값**으로 채운다 (예: 청약통장 24개월, 무주택)
3. 추정 결과를 "이렇게 이해했습니다" 카드로 보여준다
4. 추정이 판정 결과를 바꾸는 경우에만 입력을 요청한다 (스크린당 1개)

**판정 정확도 기준**

| 축 | 정확도 목표 | 검증 방법 |
|---|---|---|
| 재무 | 90% | 추정 예산 vs 실제 가용 예산 |
| 자격 | 95% | 무주택 여부·가족수·소득구간 |
| 제약 | 85% | 통근시간·입주 희망시점 |
| 선호 | 70% (L0는 무관) | 선호는 L1 이상에서만 평가 |

**왜 LLM을 판정에 쓰지 않는가.** 조건 추정에는 LLM을 쓸 수 있다(오답 비용이 낮고 근거를 제시할 수 있음). 하지만 **가능/불가 판정에는 쓰지 않는다.** 판정은 결정론적 룰 엔진(YAML + effective_date + 감사 로그)이 담당하고, LLM은 설명문 생성에만 쓴다. 사용자 재무 정보는 외부 LLM으로 전송하지 않는다. [리포트 23] [리포트 8]

#### F2. 실현 가능성 판정 (Possibility Engine)

**무엇인가.** 사용자의 조건으로 지금 가능한 선택지를 판정하고, 아닌 것은 왜 아닌지 말해주는 엔진.

**판정 축**

| 축 | 판정 내용 | 데이터 소스 | 근거 수준 |
|---|---|---|---|
| 자격 | 특별·일반공급 유형별 자격 충족 | 한국부동산원 청약 API [30] | A (공식) |
| 비용 | 취득세·중개보수·잔수리·이사·비품·대출이자 = 총부담액 | 세법 + 대기준 | A |
| 세제 | 양도소득세 중과·종부세·임대소득·등록임대 감면 | 국세청 [63][64] | A |
| 금융 | LTV·DTI·DSR·스트레스 DSR | ECOS + 기금 | A |
| 공급 | 3년 이내 공급 일정 × 입고 조건 | SH·GH·청약 [31][32] | A |
| 신뢰 | 거래 실증 여부·오래된 매물·삭제 게시 | 실거래가 API | A |

**판정 결과 3값**

| 결과 | 뜻 | 표시 |
|---|---|---|
| `POSSIBLE` | 지금 신청·계약 가능 | 금액·기한과 함께 |
| `CONDITIONAL` | 조건을 맞추면 가능 | 맞출 조건 + 그 조건이 언제까지 필요한지 |
| `NOT_NOW` | 지금은 불가 | 이유 + 다시 볼 시점 |

**세 번째 값 `UNKNOWN`이 이 제품의 신뢰 장치다.** "판단 불가"를 "불가능"으로 나오게 하지 않는다. 2026-11 기준 "전세수급지수"만 5종 값이 유통하는데 [25][26][27], 모호한 지표를 하나의 값으로 내면 그게 곧 허위다.

**구현 규칙**

- 모든 판정에는 `출처·산식·기준일`이 붙는다
- 조문 번호와 시행일이 붙는다
- 판정 불가 항목은 `UNKNOWN`으로 두고 "확인 필요" 카드로 보낸다
- 판정 입력·출력 전체를 감사 로그에 남긴다
- **매물 원문은 저장하지 않는다.** 점수·요약·링크만

#### F3. 실행 지시 (Action Planner)

**무엇인가.** "가능하다"에서 "시작한다"로 바꾸는 층. 이 제품의 핵심 차별점이자, 2026-11 기준 시장이 완전히 비어 있는 영역.

**생성 방식**

| 단계 | 내용 | 예시 |
|---|---|---|
| 1 | 첫 걸음 | "청약통장 24개월을 채우세요" |
| 2 | 그 다음 | "전용 84㎡ 이하 평형만 공급됩니다" |
| 3 | 필요한 서류 | "가족관계증명서, 주민등록등본, 소득증명" |
| 4 | 기한 | "접수는 11/20~11/24" |
| 5 | 놓치면 | "12/3 이후 차기 공고는 2027년 6월" |
| 6 | 주의 | "나중에 팔려면 6년 보유해야 세금이 줄어듭니다" |

**규칙**

- 첫 걸음은 **항상 1개, 30초 안에 끝나는 행동**
- 첫 걸음은 "제출"이 아니라 "준비"인 경우가 많다 (통장 납입, 서류 발급). 실행 저항이 낮아야 한다
- 기한이 지난 항목은 자동 제거
- 조건이 바뀌면 실행 계획도 자동 재생성

#### F4. 기한·위험 감시 (Deadline & Risk Watcher)

**무엇인가.** 놓치면 손해 보는 것만 골라서 알려주는 감시자.

| 감시 대상 | 감지 근거 | 사용자 전달 |
|---|---|---|
| 청약 접수 마감 | 청약 API + 공급 일정 | "3시간 남음" |
| 공고 간격 | SH·GH 준공 계획 | "다음 공고는 2027년 6월" |
| 세제 일정 | 법령 API 시행일 + 국세청 | "등록임대 감면 2028-12-31 일몰" |
| 세율·중과 | 국세청 고시 | "양도소득세 중과 유예 2026-05-09 종료" |
| 매물 신뢰 | 실거래가 대조 | "14개월 거래 없음" |
| 정책 진실성 | 공식 SNS 2중 확인 | "지라시입니다. 적용은 12/15부터" |

**Policy Trust (진실성 판정)**

국토교통부는 2026년 2·6·10·11월 네 차례 지라시 유포를 수사 의뢰했다. 11월 6일 유포 문건(부천·수원 권선구·안양 만안구 규제지역 추가, 고가 아파트 대출 한도 축소)은 전부 사실이 아니었고 [58][59], 국토교통부는 "정부 정책을 사칭하거나 사실을 조작해 시장에 혼란을 일으키는 행위에는 엄정 대응하겠다"라며 확인 경로를 공식 누리집·공식 SNS로 지목했다 [60].

- 단일 출처 기사는 발송하지 않는다
- **공식 소스(국토부 X·Threads·누리집) + 법령 API**가 모두 일치할 때만 확정
- 미검증 항목은 `PENDING_VERIFICATION`으로 보류, 발송 안 함
- `rejected` 항목은 감사 로그에 남겨 같은 지라시 재발 시 즉시 차단
- **정책 이벤트를 보내는 것 자체가 컴플라이언스 리스크**이므로, 표시·광고 점검(2025.7~2026.6 적발 1,412건) [61] 규칙을 선제 적용

#### F5. 신뢰 게이트

**무엇인가.** "이 매물이 지금도 거래 가능한가"를 붙이는 필터.

| 신호 | 판정 | 근거 |
|---|---|---|
| 최근 실거래 존재 | 최종 거래일 + 거래량 | 실거래가 API |
| 게시 오래됨 | 등록 후 경과일 | 게시 정보 (원문 미보관, 메타만) |
| 삭제·거래완료 | 마지막 실거래와 게시 일치 여부 | 대조 |
| 호가 대비 실거래 | 괴리율 | 실거래가 + 게시가 |
| 가격 결정성 | 실거래 존재 + 공급량 | 종합 |

서울 상위 10대단지의 전세 매물이 3.6%(2,392건/6만 6,480가구) [29]라는 사실이 이 기능의 근거다. "매물 수"를 신뢰하는 순간 사용자는 존재하지 않는 재고를 보게 된다.

#### F6. 생활어 번역층 (Plain Korean Layer)

**무엇인가.** 모든 판정 결과를 사용자가 아는 말로 바꾸는 계층.

| 시스템 용어 | 사용자 화면 |
|---|---|
| 잔여 세대 3채 | 아직 안 팔린 집이 3채 있어요 |
| DTI 43.2% | 월 상환액이 월 수입의 43%예요. 현재 대출 조건으로는 어렵습니다 |
| 전용면적 84㎡ | 집 넓이 26평 |
| 마기자 사전청약 |분양 전에 먼저 뽑는 방식(예약 매수) |
| 가점제 경쟁률 | 경쟁자 수 |
| 사용자 점유율 | 다른 지원자 대비 순위 |
| DSR 스트레스 | 금리 2%p 올랐을 때도 버틸 수 있는지 |
| 갑오세 중과 | 2년 넘게 들고 팔 때 붙는 추가 세금 |
| 조용하지 않은 세제 감면 | 받을 수 있는 세금 할인 |

**규칙.** 용어를 변환하는 것이 아니라 **판정 결과 자체를 서술형으로 다시 쓴다.** "DSR 43.2%" → "월 상환액이 월 수입의 43%라 지금 대출조건으로는 어려워요. 3.8억까지 낮추면 가능합니다."

#### F7. 실행 기록과 자산 관리

- 내가 낸 첫 걸음, 신청한 공고, 본 공고의 체크리스트
- 첫 걸음 완료 시 알림이 "다음 걸음"으로 자동 전환
- 조건 변경 이력 (무주택 기간, 통장 개월, 가족수)

### 7.3 기술

상세는 `docs/04-아키텍처.md` 참조. PRD 관점의 핵심만.

```
[공식 API Collector] → [Raw Store] → [Rule Store] → [판정 엔진] → [EventBus] → [알림]
        (Dagster)          (PostGIS)    (YAML+버전)     (결정론적)      (SSE)
                                              ↓
                                        [Plain Korean Layer]
                                              ↓
                                     [API + Next.js 대시보드]
```

| 결정 | 이유 |
|---|---|
| 모놀리트 | 1인 개발. 서비스 분리는 검증 전에 비용만 올린다 |
| 판정은 결정론적 룰 엔진 | 같은 입력 → 같은 출력. 감사 로그 필수. LLM 비결정성 금지 |
| LLM은 설명문 생성만 | 재무 정보 외부 전송 차단, 판단 일관성, 비용 |
| PostGIS | 통근 isochrone·입주 가능 지역·권역 격자 |
| 공식 오픈API만 | 전부 무료. 유료 라이선스가 없어 마진 구조가 단순 |
| SSE | 알림은 실시간성이 낮아도 됨. 주 1회 다이제스트가 대부분 |

**비용 추정 (월).** Solo ₩175,000 / Small Team ₩535,000. 지도 API가 최대 변동비다. Phase 1은 지도 API를 최소화해 월 ₩12만 이하를 목표로 한다.

| # | 가정 | 위험도 | 검증 방법 | 검증 기한 |
|---|---|---|---|---|
| A1 | 모르는 사람도 "목표 한 문장"을 입력할 의사가 있다 | 중 | 프로토타입 20명, 60초 내 완료율 70% 이상 | 2주 |
| A2 | 판정 결과가 "그래서 뭘 해야 하지"로 이어진다 | 상 | 알림→실행 전환 25% 이상 | 8주 |
| A3 | 사용자가 "확인 필요"를 신뢰한다 (불가능이 아님을) | 중 | "확인 필요" 표시 후 이탈률 측정 | 6주 |
| A4 | 실행 지시(서류·순서)의 가치가 매물 콘텐츠보다 크다 | **최상** | A/B: 첫 걸음 vs 매물 링크 — 실행률 비교 | 6주 |
| A5 | L0/L1이 실제로 L2보다 자주 대시보드를 연다 | 중 | 코호트별 D7 비교 | 8주 |
| A6 | 무료 데이터만으로 유료 가치를 낼 수 있다 | 중 | 유료 데이터 없이도 "전부 가능" 판정 커버리지 85% 이상 | 12주 |
| A7 | 세제 감시가 L1에게도 가치 있다 | 중 | 세제 관련 알림 실행률 측정 | 12주 |
| A8 | 정책 진실성 판정이 반복 사용될 가치가 있다 | 하 | 공식 SNS 수집 시작 후 재방문 | 16주 |

**A4가 가장 위험하다.** 이 제품 전체가 "실행 지시"라는 가정 위에 서 있다. A4가 틀리면 (실제로 매물 링크가 더 눌린다) 제품이 "말은 하는데 안 하는 도구"가 되어, 그때는 매물 쪽으로 흔들리는 게 아니라 **판정 자체의 깊이**로 갈아타야 한다.

## 8. 릴리스

### 8.1 Phase 구성 (상대 기간)

| Phase | 기간 | 목표 | 포함 |
|---|---|---|---|
| **Phase 0** | 2주 | 올바른 가정인지 확인 | 변호사 상담 1회(중개 아님 증명) · 비용 계산기 + 청약 판정 노트북 데모 · 인터뷰 20명 · 유료 가치 가정 검증 |
| **Phase 1** | 6~8주 | S1·S2의 순환 1회 완성 | 조건 자동 구성(F1) · 판정 엔진(F2, 주거 축) · 실행 지시(F3) · 3칸 대시보드 · 기한 감시(F4, 공급·세제만) · 신뢰 게이트(F5) · 생활어 번역(F6) |
| **Phase 2** | 6주 | S3 진입 + 범위 확대 | 투자 축 판정(세제·수익성·계약) · 정책 진실성 판정 전면 · 매물 신뢰 게이트 전면 · 실행 기록·자산 관리(F7) |
| **Phase 3** | 미정 | 관계 확장 | 리퍼럴(주요 결정 아래 참조) · 이사·수리·보험 연결 · 가족 공동 플랜 |

**Phase 0 게이트 (P0-4).** 아래 3문 중 하나라도 아니면 코드를 쓰지 않는다.

1. "돈 내겠다고 하는 사람이 5명 이상인가?"
2. "판정 결과를 보고 '이거 알아야 했다'가 나오는가?"
3. "실행 지시가 매물 링크보다 먼저 눌리는가?" (A4 검증)

**Phase 1→2 게이트.** ① 실행 사용자 1,000명 도달 ② 알림→실행 전환 25% 이상 ③ 판정 정확도 95% 이상 ④ S3용 교육 모듈(용어 사전 + 위험 체크리스트) 완료

### 8.2 Phase 1 범위

**넣는 것**
- 조건 자동 구성 (목표 1문장 → 4축 추정)
- 판정 엔진의 주거 축: 자격·총비용·세제·금융·공급
- 실행 지시
- 3칸 대시보드
- 기한 감시: 공급 일정 + 세제 일정
- 신뢰 게이트: 실거래 대조
- 생활어 번역층
- 알림: 주 1회 다이제스트 + 기한 임박 즉시
- 내 조건 확인·변경

**넣지 않는 것 (Phase 1)**
- 투자 축 판정 (S3)
- 정책 진실성 2중 검증 (Phase 2, 대신 공식 소스 인용만)
- 매물 직접 수집
- 가격 예측
- 리퍼럴·제휴
- 앱(첫 버전은 웹 반응형)

### 8.3 Phase 1 이후

**Phase 2** — S3(첫 투자) 진입. 세제 영향액 판정, 계약 리스크 체크리스트, 지식산업센터·등록임대 감면 자동 감시, 정책 진실성 판정, 자산 관리.

**Phase 3** — 리퍼럴. **단, 권유 금지 원칙을 유지한다.** 중개사·여권사·은행에 "이 고객을 연결해 드립니다"를 파는 행위는 「공인중개사법」 제18조의2 제3항과 표시·광고 규정 정면을 밟는다. Phase 3의 리퍼럴은 **"이 고객은 이미 JihaMatch에서 조건을 정리했습니다"라는 사실 전달**에만 한정하고, 상품 권유·금리 안내·수수료 부담은 파티가 한다. 또 Phase 3 이전에 대출·보험 권유 기능은 구현하지 않는다.

### 8.4 수익 모델 (최종안)

| 티어 | 가격 | 제공 |
|---|---|---|
| Free | 0원 | 월 3회 판정 · 주 1회 다이제스트 · 조건 확인 |
| Pro | 월 9,900원 | 무제한 판정 · 실행 체크리스트 · 기한 즉시 알림 · 세제 영향액 상세 · 자산 관리 |
| B2B (Phase 3) | 미정 | 중개사·여권사 대상 조건 정리 내보내기 |

**왜 개인 구독을 메인으로 하는가.** 모르는 사람의 최대 지출은 "한 번 잘못된 결정"이다. 그 비용이 월 9,900원보다 크다. 경쟁 서비스(직방 AI·KB·네이버)는 대체로 무료이고, 그럼에도 "내 조건에 맞는 판정"은 유료 회원 기능이다. JihaMatch Pro는 **유료 데이터를 쓰지 않고도** 유료 가치를 만든다(공식 API는 무료, A6 검증 대상).

**왜 리퍼럴은 Phase 3인가.** 리퍼럴은 컴플라이언스 라인을 건드리고, Phase 0의 변호사 상담이 아직 없다. 게다가 리퍼럴이 붙으면 "추천 순서"에 이해상충이 생긴다. **판정 순서를 팔 수 있는 구조는 만들지 않는다.** 이건 자부심이 아니라 리서치 결론이다. 직방·호갱노노·다방이 이미 그 싸움을 하고 있고, 그 싸움에 참가하지 않는다.

**수익 모델 미해결 항목.** 개인 구독 전환율 3%(KR4)가 Phase 1 6개월 목표인데, 이는 아직 검증되지 않았다. Phase 0 인터뷰에서 "돈 내겠다고 하는 사람이 5명 이상인가?"를 게이트로 삼는다.

## 10. 리스크와 프리모템

| 리스크 | 영향 | 대응 |
|---|---|---|
| **규제**: 중개로 오인 | 배상·격리 | 매물 원문 미보관 + 딥링크 위임 + Phase 0 변호사 상담 + 면책 상시 |
| **판정 오류** | 신뢰 붕괴. L0/L1은 한 번의 오류로 이탈 | `UNKNOWN` 상태 도입 · 근거 조문·시행일 표시 · 표본 검증 분기 1회 |
| **A4 실패** | 실행 지시 안 먹힘 | Phase 0 게이트에서 사전 검증, 실패 시 방향 전환 결정 |
| **공식 API 변경·장애** | 데이터 공백 | 소스 1+1(예: 국토부 + 한국부동산원) · 지연 분포 계측 · "최근 갱신일" 상시 표시 |
| **복잡도 저하** | 모르는 사람에겐 복잡도가 곧 벽 | jargon 0 원칙 · 3칸 고정 · 첫 걸음 1개 |
| **무료 데이터 한계** | 판정 불가 비율 상승 | 공식 API 2중화 · `UNKNOWN` 정직 표시로 위장하지 않음 |
| **정책 소스 변동** | 진실성 판정 실패 | 공식 소스 3중 교차 · rejected 목록 누적 |
| **손익** | 개인 구독 전환 3% 미달 | Phase 0 게이트에서 가격 검증. 실패 시 무료+기부 모델로 전환 |

**프리모템 (6개월 후 왜 망했을까)**

- "모르는 사람은 결국 매물 검색으로 돌아갔다. 판정은 읽지 않는다."
- "공식 API로 3년 공급을 정확히 예측하지 못했다. 추정치가 틀려서 신뢰를 잃었다."
- "청약 자격 룰이 너무 자주 바뀌어 판정이 계속 틀렸다."
- "무료 티어만 쓰고 Pro로 넘어가지 않았다."
- "L0가 실제로는 L2로 넘어가고. 타깃이 어설프게 잡혔다."
- "중개사들이 '이거 우리끼리 해도 되잖아'라고 복제했다. 그건 막을 수 없었다."

**대응**: 첫 번째와 마지막은 Phase 0 게이트에서 잡는다. 셋째는 `effective_date` 규칙과 UNKNOWN으로 낮춘다. 넷째는 Phase 0 가격 검증으로 낮춘다. 둘째는 SH처럼 표로 주는 소스를 우선 조립해 낮춘다.
